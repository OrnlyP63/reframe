# Reframe

Turn one problem into 3-5 sharper alternative framings — fast. Reframing shifts
perspective to redefine the issue so you ask better questions and reach the root
cause, not the surface annoyance. This is a brainstorming aid, not a solver and
not an interview. Do not interrogate the user; produce framings from what they
gave you.

## Why it matters
- Prevents solving the wrong problem (fix the root cause, not the symptom).
- Unlocks creativity by challenging assumed constraints and blind spots.
- Can shift a problem you *suffer* into an objective you can *tackle*.

**Canonical example — the slow elevator:** "Elevator too slow, tenants complain"
(→ expensive: new lift) reframes to "the wait feels annoying" (→ cheap: add
mirrors or music). Same facts, far better solution space.

## Quick start

1. Restate the user's problem in one neutral line: `**Problem:** ...`
2. Emit 3-5 reframes, each using a named lens (see below). Pick the lenses that
   actually fit — do not force all of them.
3. Close with one `**Recommended framing**` and a one-line why.

If the problem is vague, make best-guess framings and state the assumption in
one line — never stall to ask clarifying questions.

## Lenses (pick the 3-5 most useful)

- **Challenge assumptions** — what constraint am I treating as fixed? What if the opposite were true?
- **How → Why** — shift from "how do we force X" to "why is this happening / what do people actually need". (e.g. "How do we make staff use the tool?" → "Why do they struggle, and what would make them productive?")
- **Root problem** — "what if this isn't the real problem?" Name the problem behind it.
- **Inversion** — solve the opposite, or ask how to cause/worsen the problem on purpose.
- **Broaden context** — what external variables or perspectives outside the immediate scope am I missing?
- **Zoom in** — the smallest concrete instance where it bites.
- **Stakeholder swap** — frame it from another party's view (user, boss, customer, future self).
- **Constraint flip** — remove the constraint everyone assumes, or add one that forces creativity.
- **Emotional reframe** — restate from "thing I suffer from" to "objective I can act on" (esp. personal/productivity problems).
- **Analogy** — what is this like in another domain, and how is it solved there?

## Output format

```
**Problem:** <one-line restatement>

1. **<Lens>** — <one-line reframed problem statement>
2. **<Lens>** — <one-line reframed problem statement>
3. **<Lens>** — <one-line reframed problem statement>
   ...

**Recommended framing:** <which one to pursue> — <why, one line>
```

## Works across domains
- **Business** — an unhappy-customer complaint → an opportunity to improve experience.
- **Productivity** — "I don't have enough time" → "this task needs different prioritization".
- **Personal** — "I am lonely" → "I have time to rest and focus on myself".

## Rules
- Speed over ceremony. No multi-turn questioning.
- Each reframe is a *problem restatement*, not a solution.
- Different lenses must yield genuinely different framings — no rephrasing the same angle.
- Keep each framing to one line.
